An exemplary implementation of the Language Server Protocol in **Go**.
This project demonstrates how modern IDE features work by developing a custom language server for a custom domain-specific language called **Flow**.  
The implementation uses a parser generated by Tree-sitter. Fortunately, Tree-sitter generates not only the parser but also associated bindings for various languages, including Go.
In addition, the Go package github.com/tree-sitter/go-tree-sitter was used, which offers a range of functionalities for using such a parser.

Other dependencies, such as ready-made implementations of the protocol or similar, were deliberately avoided, as the goal of this project is to understand the LSP and abstractions from third-party libraries would therefore be counterproductive.

### **Project structure**
```
.  
├── grammar/    # The Tree-sitter grammar  
├── server/     # The Language Server (Go)  
├── vscode/     # The VS Code Client (TypeScript Extension)  
└── examples/   # Examples (.flow)
```

### **FlowLang**

FlowLang is a minimal (proof-of-concept) DSL for defining data pipelines. The individual components of a typical Flow file are as follows:

The language allows you to define where the data comes from (source):  
```hcl
source "raw_user_data" {  
    path: "/data/users.csv"  
    encoding: "utf-8"  
}
```

what types of processing are applied to this data (task): 
```hcl
task "filter_active_users" {  
    # takes the raw_user_data source output
    input: raw_user_data  
    transformer: "filter_by_column 'status' == 'active'"  
}
```

and where the data is transported to (sink): 
```hcl
sink "active_user_report" {  
    # takes the filter_active_users tasks output
    input: filter_active_users  
    path: "/reports/active_users.json"  
}
```

The grammar has been deliberately kept simple; explicit precedence rules and complex conflict resolution (ambiguities) have been avoided.  
The server analyzes the CST (Concrete Syntax Tree) generated by the Tree Sitter parser and provides editors with various features via the LSP.

### **Implemented features**

1. [Contextual Hover](https://github.com/david-hass/lsp-introduction/blob/main/server/hover.go) (textDocument/hover)  
   Move the mouse pointer over keywords such as sink, task, etc. to view documentation on the syntax.  
2. [Semantische Diagnose](https://github.com/david-hass/lsp-introduction/blob/main/server/diagnostics.go) (textDocument/publishDiagnostics)  
   The server checks logical references. For example, if a task is used in input that does not exist, this is marked as an error.

### **Build & Installation**

The project was developed in the following environment:

* Linux (Manjaro 6.16)  
* Go 1.25.1  
* npm 11.6.1  
* gcc 15.2.1

1. #### Generate the Grammar (optional)

    The C code for the parser is already located in server/parser/. If changes are made to the grammar (grammar/grammar.js), it must be regenerated:  
    ```
    cd grammar  
    npm install  
    npx tree-sitter generate && npx tree-sitter build  
    ```
    Afterwards, the files must be copied manually to ../server/parser/.  
    Alternatively, use the script: ../server/copyparser.sh

2. #### Build the server

    The server must be compiled so that the clients can start it.  
    ```
    cd server  
    go mod tidy  
    CGO_ENABLED=1 go build -o flow-lsp
    ```
    
    **Test:** Run ./flow-lsp. The server should start and wait for input. In addition, a log file should have been created under /tmp/flow\_lsp.log (under Windows usually %TEMP%\\flow\_lsp.log) with the following content:  
    ```
    2025/11/27 12:29:21 --- flowlang server started ---
    2025/11/27 12:29:21 tree sitter parser loaded.
    2025/11/27 12:29:21 flow tree sitter parser loaded
    ```

### **Integration in Neovim**

Integration could take place as follows using lazy.nvim / nvim-lspconfig.  
Insert the following into mason-lspconfig config() and adjust as necessary:  
```
local flow_lsp_path = vim.fn.expand("~/projects/lsp-introduction/server/flow-lsp")
local util = require 'lspconfig.util'

vim.lsp.config.flow = {
  cmd = { flow_lsp_path },
  filetypes = { "flow" },
  root_dir = util.find_git_ancestor() or util.path.dirname,
  capabilities = capabilities,
}
vim.lsp.enable('flow')
```
Facing Problems? Have a look here: ``:h lsp-config``

### **Integration in VS Code**

The VS Code client is located in the vscode/ folder.  
**Install dependencies:**  
```
cd vscode  
npm install
```

1. In VS Code, execute the command: Developer: Install Extension from Location...  
2. Then select the vscode folder from this repository
3. Now open the VS Code settings and search for “flow.”  
4. Under **Flow: Server Path**, enter the absolute path to your flow-lsp binary
